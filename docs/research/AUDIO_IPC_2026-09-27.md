# S22 ABOX/RDMA IPC evidence boundary (2026-09-27)

## Scope and result

This is a host-only source/evidence audit for the node-repaired, amp-off
`audio-zero-node-20260927` trial. It did not access the phone, change controls,
collect firmware payloads, or modify the kernel. The host summarizer reads a
local receipt and private kernel-delta file, emits aggregate observations only,
and never prints raw trace/log text.

No firmware-specific or route-specific driver fix is justified by current
evidence. The useful correction is to distinguish a host API entry, queued
request, host IPC send, firmware pointer callback, DMA movement, and DAPM
software power state. None of those can be inferred from a generic marker at a
different stage.

## Pinned source boundary

Source was read at
`4e5c5ad7d950e4de0688b5663965f2075654b2ad` in
`android_kernel_samsung_s5e9925`.

The active device build was reported as ABOX V4
(`CONFIG_SND_SOC_SAMSUNG_ABOX_VERSION=0x40001`, V4 enabled). The ABOX
`Makefile` selects `abox_soc_4.o`, `abox_soc.o`, and `abox_cmpnt.o` for V4;
`abox_cmpnt_3.c` is not the selected graph. In `abox_cmpnt.c`, the relevant
static route is:

```text
SPUS OUT2
  -> SPUS OUT2-SIFS0
  -> SIFS0
  -> SIFS0 PGA
  -> STMIX
  -> SIFS0 OUT (Switch)
  -> UAIF1 SPK (mux)
  -> UAIF1 PLA (UAIF1 Switch)
```

The selected V4 graph connects `SIFS0 OUT` from `STMIX`, not directly from
`SIFS0`. `SIFS0 PGA` and `STMIX` are NOPM graph widgets with no local kcontrol
in this component source. The `UAIF1 SPK` enum puts `RESERVED` at index 0 and
`SIFS0` at index 1. Static component source does not by itself establish the
active runtime topology/template or prove hardware signal flow.

The FE/BE DPCM source walk does not establish that the complete DAPM path is
powered. Likewise, backend start and BCLK enable do not establish an RDMA2
firmware callback. In `abox_rdma_trigger_ipc()` (`abox_rdma.c:1638-1653`), the
host sets `data->enabled` before requesting `PCM_PLTDAI_TRIGGER`; the request
uses atomic=true, sync=false. `abox_request_ipc()` routes this through
`abox_schedule_ipc()` (`abox.c:665-714`), which queues work and returns a local
queue result. The worker later calls `abox_ipc_send()`; successful host-side
publication/interrupt is not a firmware acknowledgement. The source's
firmware-to-host `PCM_PLTDAI_POINTER` handler stores its pointer and calls
`snd_pcm_period_elapsed()` (`abox_rdma.c:1329-1364`). `PCM_PLTDAI_ACK` is sent
from the copy path and is not trigger completion.

## Diagnostic and regressions

`tools/hardware/audio-ipc-evidence.py` is a host-only parser. It retains
device-prefix attribution for RDMA2 trigger/handler/pointer markers, keeps
unprefixed markers unattributed, counts generic asynchronous schedule entries
without channel attribution, and pairs DAPM state only with RUNNING samples.
Its semantics explicitly reject queue/sender success as firmware completion,
pointer callbacks as DMA progress proof, and DAPM software state as physical
clock/audio proof. Missing widget reads and absent markers stay unknown.

Run the deterministic host tests:

```sh
python3 -I -B tools/hardware/test-audio-ipc-evidence.py
python3 -O -I -B tools/hardware/test-audio-ipc-evidence.py
S22_AUDIO_IPC_SOURCE_TREE=/path/to/pinned/android_kernel_samsung_s5e9925 \
  python3 -I -B tools/hardware/test-audio-ipc-evidence.py
```

The optional pinned-source test is a static source-contract check only; it does
not extract, compile, or execute kernel C. It guards the asynchronous call
chain and selected V4 graph instead of the obsolete V3 graph.

For local use, pass a receipt and its kernel delta as positional paths. Output
contains counts and evidence semantics only, not the raw inputs. Do not publish
private traces or firmware/log payloads.

## Next bounded observation

Do not repeat the same zero-node stream or change gains/amp state. Before any
new PCM operation, inspect source, module compile flags, logging metadata and
the exact reader semantics for the existing ABOX debug callsites:

* `abox_schedule_ipc()` logs only `hw_irq`, size, atomic, and sync shape;
* `abox_ipc_send()` logs IPC id, task id, and message type at host sender entry;
* `abox_rdma_ipc_handler()` logs message type on the device selected from the
  incoming channel, while `abox_rdma_pointer()` logs a computed ALSA pointer.

The existing trial delta did not contain these boundaries, and the generic
schedule marker cannot attribute task/channel. Do not enable logging, flush
logs or open a payload reader as part of this metadata audit. A later passive
data read is permissible only after the exact path is proved non-consuming;
otherwise stop without reading it. Any active logging/capture change needs
independent review, including queue outcome, sender entry/return, and selected
handler device/channel/type coverage without claiming firmware completion.
Prefer existing logging facilities if their ownership and restoration can be
established; a rebuilt instrumentation kernel is not yet justified. Pair any
reviewed capture with the V4 path widgets (at
least `SIFS0 PGA`, `STMIX`, `SIFS0 OUT`, `UAIF1 SPK`, `UAIF1 PLA`) only if a
separately approved diagnostic capture proceeds. No phone mutation or
instrumentation was performed here.

### Follow-up read-only logging audit

The coordinator subsequently read only the ABOX Memlogger `name`, `enable`
and `level` metadata. `abox-mem` was enabled at level 2; `abox-file` was disabled
at level 2. PCM remained closed. No log payload was read, logging enabled,
verbosity changed, or buffer flushed. These current values do not establish
the logging policy or coverage during the earlier stream.

Pinned `abox_memlog.h` sends `abox_dbg()` messages through `dev_dbg()` and,
when enabled, through `memlog_write_printf(..., MEMLOG_LEVEL_DEBUG, ...)`.
`MEMLOG_LEVEL_DEBUG` is 5; `memlogger.c:671` rejects messages above the object's
level. Thus the present memory-log policy filters those debug markers. The
build config also leaves `CONFIG_DYNAMIC_DEBUG` unset (`CORE` alone does not
enable every callsite). Missing dmesg markers are not failed IPC evidence.

Before proposing a rebuilt instrumentation kernel, review a bounded capture
using these existing logging facilities, including module compile flags and
how exact prior settings would be restored. Reading a Memlogger character
device or its `to_string` attribute can advance shared read pointers; neither
is an innocuous passive snapshot. Do not open them or change the policy merely
because this metadata audit succeeded. A separately reviewed capture must
preserve log ownership and avoid unbounded or privacy-sensitive collection.
