# Camera: minimal V4L2 path (read-only investigation, 2026-10-08)

There is no media controller (`/dev/media*` is absent). The Pablo stack drives its
own video nodes with private conventions:
- `video101`–`105`: sensor nodes ss0–ss4 (ss0 = rear wide S5KGN3).
- `video110`–`113`: the `3xs` CSI write-DMA capture nodes.
- `video210`–`229`: per-virtual-channel nodes.
- `video120/130/140/150`: ISP stages (BYRP/RGBP/MCFP/YUVP), which need the DDK
  library and TrustZone.
- `video12`/`13`: the JPEG encoder.

From the kernel source (`include/is-video.h`, `is-device-sensor_v2.c`), a raw Bayer
frame without the ISP needs:
1. `S_INPUT` on video101, encoded as
   `stream<<24 | position<<16 | vindex<<8 | intype<<4 | leader`
   (position 0 = rear; vindex = the connected capture node, e.g. 110; leader = 1).
   The sensor mode/scenario is packed separately (`SENSOR_SCENARIO_SHIFT 28`).
2. Multi-plane `S_FMT` on the sensor and on the 3xs node (Bayer, 2040x1532 mode).
3. `REQBUFS`/`QBUF` with an image plane plus a meta plane carrying the camera2 shot
   (SHOT_MAGIC), then `STREAMON`.
