# Corrected fence semantics and SGPU VM fault

The earlier diagnostic patch condition was wrong and must not be used:
libdrm's installed /usr/include/libdrm/amdgpu.h documents expired == 0 as
“fence is not expired” and expired != 0 as completed. Therefore the
one-variable diagnostic condition is if (!pr && expired). The corrected patch
is in radv-sync-real-fence.patch; no Mesa source was modified here.

The new trace establishes a deeper failure before any correctness claim:

* DRM_IOCTL_AMDGPU_CS returned 0.
* DRM_IOCTL_AMDGPU_WAIT_CS returned 0.
* The patched source logged fence poll ret=0 expired=1.
* Kernel tail reports SGPU gfxhub page fault for gpu-compute-pro,
  vmid=2, address 0x0000ff78f6c54000, client TCP (0x8),
  PERMISSION_FAULTS=0x4, MAPPING_ERROR=0x1, RW=0x1.
* The Vulkan fence still returned VK_ERROR_UNKNOWN; this is not a valid
  completion or model result.

## Concrete address/ABI observations

The patched source logs IB BO VAs such as 0xffff800100001000,
0xffff800100016000, and 0xffff80010002a000. RADV's normal BO allocator
stores the GPU VA returned by amdgpu_va_range_alloc and maps it with
amdgpu_bo_va_op; the CS path puts that VA directly into
chunk_data[i].ib_data.va_start. The fault address 0x0000ff78f6c54000 is not
one of the logged IB addresses, so this is not evidence that the IB pointer
itself is the faulting address. It is a shader TCP memory access generated by
a descriptor/resource address or an SGPU address-width/mapping incompatibility.

Relevant source locations for the next isolated audit are:

* src/amd/vulkan/radv_queue.c:261: buffer descriptor construction via
  ac_build_buffer_descriptor.
* src/amd/vulkan/radv_queue.c:546-572: descriptor BO VA emitted into
  user-data and added to the CS.
* src/amd/vulkan/winsys/amdgpu/radv_amdgpu_bo.c:371-378: BO VA allocation
  and base.va assignment.
* src/amd/vulkan/winsys/amdgpu/radv_amdgpu_bo.c:402: VA mapping.
* src/amd/vulkan/winsys/amdgpu/radv_amdgpu_cs.c:1750-1889: IB chunk and
  SGPU submit/fence handling.

No safe address truncation or descriptor rewrite is proposed yet. The fault
could reflect SGPU's supported VA width, a descriptor base address assembled
for standard RDNA2 rather than this downstream interface, or a kernel mapping
contract mismatch. A next experiment must dump the exact output-buffer
descriptor words and corresponding BO GPU VA from the private source, then
compare the descriptor address against the kernel fault; it must not dispatch
more workloads until that mapping is understood.
